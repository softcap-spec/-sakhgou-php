3Архитектура: единый диспетчер

Вместо того чтобы дёргать Telegram/Макс в каждом обработчике — один центральный хелпер, который рассылает по всем включённым каналам пользователя:

Событие (бронь/сообщение)→ notify_dispatch($user_id, $event, $data)→ определяет каналы юзера→ In-appEmailTelegramМакс
  • Новый файл includes/notify.php — диспетчер + сендеры каналов (всё в try/catch, сбой бота не ломает бронь/чат).
  • Сендеры: tg_send($chat_id, $text), max_send($dialog_id, $text) — обёртки над HTTP API.
  • Поля привязки в users: telegram_chat_id, max_dialog_id + notify_prefs (JSON: какие события в какие каналы).

4Telegram — как прикрутить

  1. Бот: создаётся у @BotFather → выдаётся token.
  2. Привязка пользователя: в профиле кнопка «Привязать Telegram» → ссылка t.me/<bot>?start=link_<секрет>; юзер жмёт /start, бот по deep-link-параметру мапит секрет → user_id и сохраняет chat_id.
  3. Приём сообщений ботом: вебхук на /api/tg-webhook (секрет в URL) — проще всего на Timeweb.
  4. Отправка: POST https://api.telegram.org/bot<token>/sendMessage с chat_id + text.

5«Макс» (max.ru) — как прикрутить

«Макс» — мессенджер и платформа VK. Для разработчиков есть Max Bot API (документация на dev.max.ru/docs-api): бот получает токен, отправка сообщений — POST /messages в диалог/группу/канал.

  1. Бот: создаётся в кабинете разработчика «Макс» → выдаётся token.
  2. Привязка: юзер пишет боту → получаем dialog_id (id диалога) → сохраняем в max_dialog_id.
  3. Отправка: POST /messages с dialog_id + текст (аналог Telegram sendMessage).
  4. Приём: вебхук или long poll (по аналогии с Telegram).
⚠️ Публикация бота в каталог «Макс» — только через верифицированное юрлицо РФ (самозанятый не подходит — это не юрлицо). Но для рассылки уведомлений каталог не нужен: бот работает и без него — юзеры находят его по прямой ссылке/приглашению, пишут ему, и мы шлём уведомления в диалоги. Каталог — это только витрина для поиска; для уведомлений он не требуется.

6Доставка: синхронно или очередь

Синхронно (проще)

Слать прямо в обработчике события, с таймаутом ~3с и try/catch. Для текущих объёмов (десятки заявок/день) достаточно. Минус: при зависшем API бота страница слегка притормаживает.

Очередь + cron (надёжнее)

Писать в таблицу notification_queue, а cron раз в минуту разбирает её и шлёт (с ретраями). Страница не блокируется, уведомления не теряются при сбое бота. Рекомендую как целевой вариант.

7Рекомендуемый план внедрения

  1. MVP (30–60 мин): Telegram без привязки — один бот, один chat_id (ваш/оператора) получает «новая бронь» и «новое сообщение». Мгновенная польза.
  2. Этап 2: привязка Telegram в профиле (deep-link) — каждый продавец получает свои уведомления.
  3. Этап 3: «Макс» (max.ru) по той же схеме — POST /messages.
  4. Этап 4: очередь + cron, настройки «какие события в какие каналы» на юзера.

8Что нужно от тебя

  • Telegram-бот: прислать token от @BotFather (или дай команду — дам пошаговую инструкцию).
  • «Макс»-бот: токен из кабинета dev.max.ru (когда дойдём до этапа 3).
  • Какие события первыми: брони + сообщения, или что-то ещё (отзывы, модерация).
  • Кому слать на MVP: один общий чат или сразу привязка по пользователям.
