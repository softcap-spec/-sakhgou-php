Календарь продавца + свободные даты в объявлении

Дизайн-предложение · СахGO · август 2026

1Общая идея

Брони — единственный источник занятости. Календарь — это просто удобный вид поверх существующей таблицы bookings. Ручные записи (оффлайн-клиенты, «занято лично») — это те же записи в bookings, но с новым статусом blocked и source = manual. Тогда:

  • календарь, «Ко мне», «Мои брони» и проверка занятости на объявлении читают одни и те же данные — ничего не разъедется;
  • оффлайн-клиент, добавленный вручную, автоматически блокирует даты для онлайн-бронирования;
  • подтверждённая онлайн-бронь появляется в календаре сама.

Изменения в БД минимальные: status + 'blocked' (varchar — уже совместим), колонки source, guest_name (для ручных записей), guest_id становится nullable.

2Где живёт календарь — варианты

A Вкладка «Календарь» в кабинете

Новая вкладка рядом с «Ко мне». Сетка месяца на всю ширину, клик по дню — детали, кнопка «Добавить».

Рекомендую для v1

B Мини-календарь внутри «Ко мне»

Список заявок остаётся главным, календарь сбоку как виджет. Меньше места, cramped на мобильных.

компромисс

C Отдельная страница /calendar

Полноценный ежедневник с неделями/днями. Максимальный простор, но отдельный маршрут и больше работы.

v2, если v1 понравится

3Функционал ежедневника (v1)

  • Сетка месяца: навигация ← месяц →, кнопка «Сегодня»; дни с событиями помечены цветными чипами;
  • Цвета статусов: подтверждена ожидает занято вручную — легенда рядом;
  • Фильтр по объявлению: «Все объявления» или конкретное (селект сверху);
  • Клик по дню: панель со списком броней этого дня (гость, объявление, статус) + кнопка «Добавить занятие»;
  • Ручное добавление: модалка — даты (с/по), объявление, имя клиента (текстом, «клиент с авито»), телефон, цена (или «без цены»), заметка;
  • Редактирование/удаление: клик по брони в календаре → модалка правки (даты, статус, имя, цена) / удалить. Ручные правки не трогают гостя (у ручных нет guest_id);
  • Конфликты: при добавлении пересекающегося занятия — предупреждение «эти даты уже заняты: …» + кнопка «Отклонить ожидающую и занять»;
  • Прошлое: дни до сегодня приглушены; правки прошлого разрешены (для истории), новое вручную — только с сегодня.

4Свободные даты в объявлении — варианты

1 Мини-календарь + блокировка в поле дат

Под формой брони — календарик на 2 месяца: занятые дни зачёркнуты/затемнены. В полях дат — валидация: нельзя выбрать занятый диапазон. Данные — API /api/availability.

Рекомендую

2 Список занятых диапазонов текстом

«Занято: 10–13 сентября, 20–25 сентября». Минимум кода, но UX слабее — гость сам сопоставляет.

быстрый костыль

3 Только валидация на отправке

Гость не видит занятость, но при пересечении получает ошибку «эти даты заняты». Самое простое и уже почти есть.

база, без неё никак

Рекомендация: 3 как фундамент (проверка уже работает), 1 поверх — календарик + валидация в полях. Вариант 2 — как запасной, если календарик захочется отложить.

5Правила, которые нужно решить

ВопросМоё предложение
Блокируют ли даты брони со статусом «ожидает»?Да, но с таймером: pending живёт 48 часов, потом автоматически отклоняется («не подтвердил вовремя»). Иначе один гость заморозит даты навсегда.
Продавец вручную занял даты, а там чужая «ожидает»Предупреждение + выбор: «Отклонить ожидающую» или «Отмена».
Кто видит детали ручных записей в объявлении?Только «даты заняты». Имя/телефон оффлайн-клиента — приватно, только продавцу.
Туры: одна дата или диапазон?Диапазон (многодневные туры есть). Однодневный тур = вых = дата выхода.
Уведомления в «Макс»?Онлайн-бронь → продавцу (уже есть). Ручную запись в «Макс» не шлём — продавец сам её внёс.
